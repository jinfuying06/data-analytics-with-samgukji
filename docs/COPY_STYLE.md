# 화면 문구 작성 기준

## 기준 문체

쉽고 정확한 설명을 사용하되, 학습자를 어린아이처럼 대하지 않는다.

- 설명·결과·피드백: 차분한 `합니다·입니다`체.
- 핵심 질문: `~할까요?` 또는 `~무엇일까요?`.
- 행동 안내: `~확인해 보세요`, `~선택해 보세요`.
- 버튼·활동 제목: `~하기`, 상태 표시: `진행 전·완료·저장됨`.
- 과장된 감탄, 장수의 가상 명령, 빈 칭찬 대신 무엇을 확인했는지 설명한다.

이 기준은 현재 6단계 앱에 적용한다. 과거 어린이용 프로토타입 문서의 해요체 기준보다 이 기준을 우선한다.

## 용어

| 사용 용어 | 의미 |
|---|---|
| 분석 대상 | 선택한 기준에 따라 포함한 인물. 실제 참전을 확정한 명단이 아님 |
| 등장 문단 수 | 인물의 이름이 포함된 문단 수. 실력·능력·공헌도가 아님 |
| 비교 점수 | 텍스트 지표에 선택한 가중치를 적용한 값 |
| 분석 자료 | 연의·정사 본문·정사 주석 등 계산에 사용하는 자료 |
| 연합 비교 지수 | 선택한 점수와 바람 가정을 적용한 학습용 지수. 실제 승률이 아님 |
| 순서 | 여섯 단계 목록. 마친 순서 아래에 확인한 수치와 해석(학습 기록)을 함께 보여 준다. 별도의 학습 기록 패널은 두지 않는다 |
| 가정 실험 | 인물·바람·점수·기록 중 하나를 바꿔 결과를 비교하는 활동. 화면에는 영어 “What-if”를 쓰지 않는다 |

## 원문·가정·해석 구분

- 번역된 근거 문단은 원문 자료로 보존한다. 말투를 맞추기 위해 고치지 않는다.
- 인물 옆의 질문은 학습을 위한 재구성임을 표시한다. 사료 인용으로 제시하지 않는다.
- 소설과 역사책의 비중 차이만으로 과장 여부를 단정하지 않는다.
- 키워드 동시 출현을 실제 전투 능력이나 공헌도로 표현하지 않는다.
- 전투 효과의 수를 실제 함선 피해 규모처럼 설명하지 않는다.

## 구현과 검증

단어의 종결어미를 순서대로 치환하던 방식을 문장·문맥 단위의 동시 치환으로 바꾸었다. 현재는 수정 문구를 `prototype/red-cliff-lab/src/20-markup.html`, `40-app.js`, `70-learning-journey.js`에 직접 반영했다. 빌드 중 문구 치환은 하지 않는다. `scripts/site-copy.json`은 이전 문구 교정의 이력으로 남긴다.

6단계의 제목·설명·조작 안내·오답/정답 피드백·동적 결과·자료 화면을 DOM에서 추출해 검토했다. 데이터, 집계, 가중치, 시뮬레이션 계산은 유지한다. 실제 브라우저의 시각·모바일 검수는 관리형 미리보기 환경 부재로 미완료다.

## 현재 화자: 시간을 건너 기록을 펼치는 기록관

- 기본은 정중한 존댓말이다. 행동 안내는 “~살펴보시지요”, “~남겨 주십시오”로 차분하게 쓴다.
- 정답·오답·결과 피드백은 기록관 말투를 빼고 바로 말한다. 맞으면 “맞습니다.”, 틀리면 “다시 생각해 보시지요.”로 시작하고, 결과 설명은 “~했습니다”로 끝낸다. “~군요”, “그렇지요”, “그렇게 읽을 수 있겠군요” 같은 맞장구는 쓰지 않는다.
- 문장 정리는 stop-slop-ko 기준을 따른다. em-dash(—) 장식, 번역투(“~을 통하여”, “~에 있어서”, “~되어지다”), 조사 앞 공백을 쓰지 않는다. 변경 후 `slop_scan.py`로 `frontend/public/learning/index.html`을 검사한다.
- 첫 만남에서만 기록관의 정체를 짧게 밝힌다. 사용자를 반복해서 ‘그대’나 ‘나그네’로 부르지 않는다.
- 낯선 고어, 하옵니다체, 꾸짖는 명령투는 쓰지 않는다. 버튼은 ‘기록 펼치기’, ‘명단에 넣기’처럼 짧고 구체적으로 쓴다.
- 표의 열 이름·계산식·자료명·숫자는 정확한 용어를 유지한다. 결과 피드백은 함께 근거를 읽고 해석하는 목소리로 쓴다.
- 기록관의 말은 창작 안내 문구다. 원문 인용·생성 데이터·실제 역사 기록으로 제시하지 않는다. `30-data.js`와 DB, 계산 규칙은 변경하지 않는다.
- 문구는 소스에 직접 반영한다. 종결어미를 일괄 치환하거나 런타임에서 문자열을 바꾸는 방식은 사용하지 않는다.
- 기록관은 시간을 건너 기록을 펼치는 인물이므로 화면 문구에 영어를 섞지 않는다. 영문 라벨(“ARCHIVE”, “CHAPTERS” 등)도 한국어로 쓴다. 자료 출처를 밝히는 기술 용어(SQLite, FastAPI)만 예외다.
- 질문은 근거를 먼저 보여 준 뒤에 한다. 답이 정해진 질문은 고르는 즉시 “맞습니다.”나 “다시 생각해 보시지요.”로 알려 준다. 학습 확인 퀴즈는 정답을 고른 뒤에도 다른 보기를 눌러 이유를 볼 수 있다.
- 눌러서 결과만 미리 보는 버튼은 “계산해 보기”처럼 쓰고, 학습 진행에 반영되는 버튼과 구분한다.
- “A가 아니라 B”, “A뿐 아니라 B”, “A이지 B는 아니다”처럼 앞을 부정하고 뒤를 말하는 구문은 쓰지 않는다. 말하려는 B만 “~는 B입니다”로 쓴다. 학습자가 오해하기 쉬운 점은 “~가 아닙니다”처럼 한 문장으로 따로 밝힌다.
- 정답·오답 피드백은 퀴즈, 카드, 질문 어디서나 같은 모양으로 쓴다. 테두리 상자 없이 색이 든 첫 마디(“맞습니다.”, “다시 생각해 보시지요.”)와 설명 한 줄만 둔다. 오답 설명에는 “다시”를 반복하지 않는다.
## 화면 이름 기준

| 대상 | 이름 | 쓰는 곳 |
|---|---|---|
| 질문과 예상을 남기는 메인 화면 | 시작 | 메뉴·탭은 “시작”, 되돌아가는 버튼은 “시작으로”. 문장 속의 부사 “처음에 남긴 예상”은 화면 이름이 아니다 |
| 첫 접속 때 나오는 오프닝 연출 | 서막 | 다시 여는 버튼은 모두 “서막 다시 보기”, 건너뛰는 버튼은 “건너뛰기” |
| 여섯 단계 | 순서 | 목록 이름은 “순서”, 각 항목의 번호는 “1장, 2장”으로 쓴다. 숫자만 박스에 넣지 않고, 체크 표시도 붙이지 않는다. 완료한 장은 라벨 색으로 구분한다. 진행은 “완료 0 / 6” |
| 질문 모음 | 가정 실험 | 메뉴·탭·6단계 이름 모두 “가정 실험”. 질문은 난이도에 따라 “기초 · 심화 · 응용”으로 묶고, “단계”라는 말은 쓰지 않는다(“장”과 겹침) |
| 내가 만드는 질문 | 직접 질문 만들기 | 가정 실험 화면에서 질문 목록 바로 아래에 펼쳐 둔다. 고르면 결과가 바로 계산된다. 진행 숫자와 관련이 없으므로 그에 대한 안내 문장은 두지 않는다 |
| 데이터 화면 | 자료와 집계 기준 | 메뉴 이름 |
| 사이드바의 메뉴 묶음 | 바로가기 / 순서 / 참고 | “시작”은 메인 화면 이름이므로 묶음 이름으로 쓰지 않는다 |

- “시작하기”는 메인 화면에서 첫 순서를 여는 행동 버튼이다. 화면 이름 “시작”과 같은 화면 안에 있다.
- “오프닝”, “홈”, “메인”, “처음 화면”, “시네마” 같은 말은 화면 이름으로 쓰지 않는다.
- 한 대상에는 이름 하나만 쓴다. 메뉴, 버튼, 접근성 이름(aria-label)이 서로 다르면 안 된다.
- 사이드바는 “시작” 화면에서만 숨긴다. 그 밖의 모든 화면은 어디서 들어와도 같은 모양이다.
- 사이드바 맨 위에 “완료 N / 6”과 진행 막대를 둔다. 숫자는 지금 선택한 질문에서 학습 확인 퀴즈를 맞힌 장의 수이다. 막대는 `.prog-bar` 전용 클래스를 쓴다(`.bar`는 막대 그래프 행의 그리드라서 쓰면 폭이 틀어진다). 메뉴 항목에는 한자(始, 假, 典) 같은 아이콘 글자를 붙이지 않는다.

## 진행 표시 기준

| 위치 | 표시 | 뜻 |
|---|---|---|
| 사이드바 맨 위 | 질문 이름 + “완료 N / 6” + 막대 | 지금 하는 질문 하나에서 학습 확인 퀴즈를 맞힌 장의 수 |
| 가정 실험 질문 카드 | 완료: 초록 테두리와 “완료”. 진행 중: “N/6 완료”와 작은 막대. 지금 하는 질문: 주황 테두리 | 그 질문의 진행 상태 |
| 가정 실험 머리말 | “완료 N / 9 · 진행 중 M” | 질문 9개 중 끝낸 것과 하고 있는 것 |

- 사이드바의 순서 목록과 진행은 질문 하나의 흐름이므로, 질문을 고르는 가정 실험 탭에서는 숨긴다.
- 숫자만 단독으로 쓰지 않는다. 무엇을 센 것인지 글로 붙인다. 예: “5/6 완료”.
- 직접 질문 만들기는 이 숫자들에 들어가지 않는다.
