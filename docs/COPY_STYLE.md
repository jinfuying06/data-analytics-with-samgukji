# 화면 문구 작성 기준

## 기준 문체

쉽고 정확한 설명을 사용하되, 학습자를 어린아이처럼 대하지 않는다.

- 설명·결과·피드백: 차분한 `합니다·입니다`체.
- 핵심 질문: `~할까요?` 또는 `~무엇일까요?`.
- 행동 안내: `~확인해 보세요`, `~선택해 보세요`.
- 버튼·활동 제목: `~하기`, 상태 표시: `진행 전·완료·저장됨`.
- 과장된 감탄, 장수의 가상 명령, 빈 칭찬 대신 무엇을 확인했는지 설명한다.

이 기준은 현재 6단계 앱에 적용한다. 과거 어린이용 프로토타입 문서의 해요체 기준보다 이 기준을 우선한다.

## 용어

| 사용 용어 | 의미 |
|---|---|
| 분석 대상 | 선택한 기준에 따라 포함한 인물. 실제 참전을 확정한 명단이 아님 |
| 등장 문단 수 | 인물의 이름이 포함된 문단 수. 실력·능력·공헌도가 아님 |
| 비교 점수 | 텍스트 지표에 선택한 가중치를 적용한 값 |
| 분석 자료 | 연의·정사 본문·정사 주석 등 계산에 사용하는 자료 |
| 연합 비교 지수 | 선택한 점수와 바람 가정을 적용한 학습용 지수. 실제 승률이 아님 |
| 학습 기록 | 각 단계에서 확인한 수치와 해석 |

## 원문·가정·해석 구분

- 번역된 근거 문단은 원문 자료로 보존한다. 말투를 맞추기 위해 고치지 않는다.
- 인물 옆의 질문은 학습을 위한 재구성임을 표시한다. 사료 인용으로 제시하지 않는다.
- 소설과 역사책의 비중 차이만으로 과장 여부를 단정하지 않는다.
- 키워드 동시 출현을 실제 전투 능력이나 공헌도로 표현하지 않는다.
- 전투 효과의 수를 실제 함선 피해 규모처럼 설명하지 않는다.

## 구현과 검증

단어의 종결어미를 순서대로 치환하던 방식을 문장·문맥 단위의 동시 치환으로 바꾸었다. 현재는 수정 문구를 `prototype/red-cliff-lab/src/20-markup.html`, `40-app.js`, `70-learning-journey.js`에 직접 반영했다. 빌드 중 문구 치환은 하지 않는다. `scripts/site-copy.json`은 이전 문구 교정의 이력으로 남긴다.

6단계의 제목·설명·조작 안내·오답/정답 피드백·동적 결과·자료 화면을 DOM에서 추출해 검토했다. 데이터, 집계, 가중치, 시뮬레이션 계산은 유지한다. 실제 브라우저의 시각·모바일 검수는 관리형 미리보기 환경 부재로 미완료다.

## 현재 화자: 시간을 건너 기록을 펼치는 기록관

- 기본은 정중한 존댓말이다. “~군요”, “~지요”, “~살펴보시지요”, “~남겨 주십시오”로 차분하게 안내한다.
- 첫 만남에서만 기록관의 정체를 짧게 밝힌다. 사용자를 반복해서 ‘그대’나 ‘나그네’로 부르지 않는다.
- 낯선 고어, 하옵니다체, 꾸짖는 명령투는 쓰지 않는다. 버튼은 ‘기록 펼치기’, ‘명단에 넣기’처럼 짧고 구체적으로 쓴다.
- 표의 열 이름·계산식·자료명·숫자는 정확한 용어를 유지한다. 결과 피드백은 함께 근거를 읽고 해석하는 목소리로 쓴다.
- 기록관의 말은 창작 안내 문구다. 원문 인용·생성 데이터·실제 역사 기록으로 제시하지 않는다. `30-data.js`와 DB, 계산 규칙은 변경하지 않는다.
- 문구는 소스에 직접 반영한다. 종결어미를 일괄 치환하거나 런타임에서 문자열을 바꾸는 방식은 사용하지 않는다.
