# 데이터 모델링 방식과 분석 기준

- 작성일: 2026-10-30
- 용도: PRD의 '데이터 정의·모델링' 절에 옮겨 쓰기 위한 정리본
- 근거 코드: `scripts/` 파이프라인, `scripts/build_red_cliff_seed.py`, `scripts/build_red_cliff_lab_data.py`, `prototype/red-cliff-lab/src/40-app.js`, `frontend/lib/simulation.ts`, `backend/main.py`
- 수치는 2026-10-30에 `data/seed/red_cliff.db`와 `data/processed/samgukji.db`를 직접 조회한 값이다.

---

## 1. 전체 구조 한눈에 보기

```
위키문헌 원문 (정사 65卷, 연의 120回)
  └─ data/raw/wikisource/{정사,연의}/*.json        ← 1층: 원문
       └─ 인물별 분리·태깅 (규칙 기반)
            └─ data/processed/정사/인물별/*.json   ← 2층: 인물 단위 가공
               data/processed/연의/인물별_언급/*.json
                 └─ data/processed/samgukji.db      ← 3층: 전체 통합 DB (로컬)
                      └─ data/seed/red_cliff.db     ← 4층: 공개 seed (43~50회만)
                           ├─ backend API (FastAPI)
                           ├─ frontend/lib/seed-snapshot.json
                           └─ prototype/.../30-data.js (학습 지표)
```

설계 원칙 (모든 층에 공통):

1. **역추적 가능성**: 모든 행은 원문 URL(`source_url`)을 갖고, 분석 수치는 원문 문단까지 되짚을 수 있어야 한다.
2. **불확실성은 지우지 않고 기록**: 규칙으로 확정하지 못한 항목은 삭제하지 않고 `data/processed/needs_review.json`에 사유·URL과 함께 남긴다.
3. **판정 방법 기록**: 자동 매칭 결과에는 `tagging_method`(현재 전부 `규칙`)를 남긴다.
4. **재생성 가능**: 가공·통합 단계는 매번 처음부터 다시 만들 수 있게 한다. 단, 시간이 오래 걸리는 번역 데이터는 재생성 대상에서 제외해 보존한다.
5. **연의와 정사는 섞지 않는다**: 두 자료는 별도 테이블로 두고, 비교할 때만 같은 인물명으로 잇는다.

## 3. 인물 식별(엔티티 정규화) 기준

### 3.1 표준 인물명(canonical name)
- 표준 이름은 **정사 인물별 파일의 `인물명`(번체 한자)** 을 기본으로 한다.
- 정사에 열전 없이 帝紀·先主傳 등으로만 실린 군주급 인물(劉備, 曹操, 孫權 등)은 수작업 목록(`CURATED`)으로 표준 이름에 추가한다.
- 결과물: `data/processed/인물명_정규화.json` (표준명 → 별칭 목록)

### 3.2 별칭(자·호·칭호)
- 주요 인물의 자(字)·별호·칭호를 수작업으로 보강한다. 예: 諸葛亮 ← 孔明, 諸葛孔明, 臥龍 / 曹操 ← 孟德, 曹公, 阿瞞
- **한 글자 지칭(예: `操` = 曹操)은 넣지 않는다.** 문맥 의존이 커서 오탐 위험이 높기 때문이다. → 알려진 한계: 한 글자로만 불린 문단은 집계에서 빠진다.
- 정사 분리 단계에서 테이블에 없는 이름은 간체→번체 변환(OpenCC s2t) 후 비교한다.

## 4. 정사(三國志) 모델링: 卷 → 인물 전기

### 4.1 분리 규칙 (`split_persons.py`)
우선순위대로 적용한다.

1. **1순위**: 원문 헤더의 `listed_persons`(본전 주인공 목록)가 본문에 처음 나오는 위치를 경계로 삼는다.
2. **2순위**: 열전 서두 패턴 `OOO字XX，YYY人也`를 인물 시작 경계로 본다. 여성 인물은 `시호+성씨+皇后/太后/夫人/妃，출신지人` 패턴(서술어가 섞인 오탐은 제외).
3. **보조 패턴**: 蜀書의 `先主/後主太子OO`, 종실·제기 권의 `OO王/公/侯(諱)이름` (경계가 하나도 안 잡힌 卷에만 적용).
4. **종실/왕공 폴백**: 패턴이 0건이면 `listed_persons` 순서를 본문 등장 순서에 대응시킨다. 이렇게 분리한 인물은 `is_minor_biography = 1`로 표시하고, 짧다는 이유만으로 검토 대상에 넣지 않는다.
5. 배송지 주석(〈 〉 안)은 경계 탐지 시 가려서 오분할을 막는다. 전기 본문에는 주석이 포함된 채 저장된다.

### 4.2 검토 대상(needs_review) 조건
- 모든 규칙을 써도 탐지 인물이 0명인 卷
- `listed_persons`와 패턴 매칭 결과가 충돌하는 卷
- 卷 시작부 텍스트가 어느 인물에도 귀속되지 않는 경우

알려진 잔여 한계: 卷34의 先主甘皇后·敬哀皇后·張皇后는 분리되지 않는다.

### 4.3 진영(국가) 분류 기준
- **卷 번호로 결정한다**: 卷1~30 = 魏, 卷31~45 = 蜀, 卷46~65 = 吳 (원문으로 경계 확인).
- 즉 '그 인물이 실제로 어느 편이었나'가 아니라 **'정사가 어느 서(書)에 실었나'** 를 따른다. 그래서 袁紹·呂布·董卓·劉表처럼 위와 싸운 인물도 魏書에 실려 있으면 `魏`로 분류된다. (분석 단계에서 사망자 제외 규칙으로 보정, 6.1 참고)

## 5. 연의(三國志演義) 모델링: 回 → 인물 등장 기록

### 5.1 태깅 규칙 (`tag_yeonui_persons.py`)
- 분석 단위: **문단**. 回 본문을 줄바꿈(`\n`)으로 나눈 한 덩어리.
- 문단마다 별칭 테이블의 모든 별칭을 **긴 것부터** 찾고, 이미 매칭된 글자 위치는 다시 쓰지 않는다. (예: `諸葛瑾`이 먼저 잡혀 `諸葛`류 짧은 별칭과 겹치지 않음)
- 한 문단에 같은 인물이 여러 번 나와도 그 문단은 1회로 센다.
- 回 제목(`chapter_title`)에 나온 인물은 '주연 후보'로 따로 뽑는다(현재 저장 데이터에는 쓰이지 않음).
- 한 명도 매칭되지 않은 回는 `needs_review`로 보내고 기록을 만들지 않는다.

### 5.2 저장 단위 (grain)
- **(인물, 회차) 한 쌍이 한 행**. 해당 회차에서 그 인물이 나온 문단 전체를 `excerpt`에 JSON 배열로 담는다.
- 따라서 '등장 회차 수'는 행 수, '등장 문단 수'는 `excerpt` 배열 길이로 계산한다.

### 5.3 공동등장(co-occurrence) 정의
- **같은 회차에 함께 등장하면 1회**. 두 인물이 함께 나온 회차 수가 간선 가중치다.
- 장면·문단 단위 겹침이 아니다. 문단 위치 정보를 저장하지 않아 현재 데이터로는 장면 단위를 판별할 수 없다.
- 쌍은 이름을 정렬해 `(person_a < person_b)`로 한 번만 저장한다.

## 6. 공개 seed DB (`data/seed/red_cliff.db`) 생성 기준

### 6.1 범위 기준
| 기준 | 내용 |
|---|---|
| 스토리라인 | 적벽대전 (`storyline = red-cliff`) |
| 회차 범위 | 연의 **제43~50회** (8회) |
| 인물 범위 | 위 범위 연의 기록에 1회 이상 등장한 인물만 |
| 정사 데이터 | 위 인물들의 정사 전기만 복사 (전기 자체는 卷 전체 범위) |
| 번역 | 위 인물의 정사 번역, 43~50회 문단 번역만 복사 |
| 공동등장 | 전체 DB 값을 복사하지 않고 **43~50회 안에서 다시 계산** (전체 120회 통계가 새어 나가지 않게) |

### 6.2 생성 절차와 안전장치
1. 로컬 전체 DB `data/processed/samgukji.db`를 원본으로 읽는다(원본은 수정하지 않음).
2. 임시 파일(`red_cliff.tmp.db`)에 스키마를 만들고 데이터를 채운다.
3. `PRAGMA integrity_check`가 `ok`일 때만 기존 seed를 교체한다. 실패하면 임시 파일을 지우고 기존 seed는 그대로 둔다.
4. 범위 정보는 `seed_metadata` 테이블에 기록한다 (`chapter_start=43`, `chapter_end=50`, `source_scope=삼국지연의 제43회~제50회`).
5. 프런트엔드 스냅샷(`frontend/lib/seed-snapshot.json`)에는 seed 파일의 SHA-256과 커밋 해시를 함께 기록해 어떤 seed에서 나온 값인지 추적한다.

### 6.3 스키마

| 테이블 | 키 | 한 행의 의미 | 주요 컬럼 |
|---|---|---|---|
| `seed_metadata` | `key` | seed 범위 설정 하나 | `key, value` |
| `jeongsa_persons` | `name` | 정사 인물 한 명의 전기 | `source_juan`(卷), `country`(魏/蜀/吳), `biography`(주석 포함 원문), `source_url`, `is_minor_biography`, `mentioned_relatives`(JSON) |
| `yeonui_mentions` | `(name, chapter)` 유일 | 한 인물이 한 회차에 등장한 기록 | `chapter_title`, `excerpt`(등장 문단 JSON 배열), `tagging_method`, `source_url` |
| `cooccurrence_edges` | `(person_a, person_b)` 유일 | 두 인물이 함께 나온 회차 수 | `count` |
| `jeongsa_translations` | `name` | 정사 전기 한국어 번역 | `biography_ko, translated_at, translated_by` |
| `yeonui_paragraph_translations` | `(chapter, paragraph_zh)` 유일 | 연의 문단 하나의 번역 | `paragraph_zh, paragraph_ko, translated_at, translated_by` |

인덱스: `yeonui_mentions(name)`, `yeonui_mentions(chapter)`.
연결 키: 모든 테이블은 **표준 인물명(번체 한자)** 으로 이어진다. 번역 문단은 원문 문단 문자열(`paragraph_zh`)로 `excerpt` 속 문단과 맞춘다.

## 7. 분석 지표 정의 (seed DB → 학습 지표)

### 7.1 기본 집계 지표

| 지표 | 정의 | 계산 | 쓰는 곳 |
|---|---|---|---|
| **등장 회차 수** | 선택 범위에서 인물이 등장한 서로 다른 회차 수 | `COUNT(DISTINCT chapter)` | PRD F02 분석 퀘스트, `/api/analytics/appearances`, `/api/network` 노드 크기 |
| **존재감(등장 문단 수)** | 이름이 들어간 연의 문단 수 (한 문단 여러 번 = 1) | `excerpt` 배열 길이의 합 | 학습 프로토타입 1·2단계 |
| **공동등장 수** | 두 인물이 함께 나온 회차 수 | `cooccurrence_edges.count` | 관계망(`/api/network`, 기본 `min_count=5`), 6단계 |

정렬 기준(동점 처리): 값 내림차순, 같으면 인물명 오름차순.
해석 기준: 위 수치는 모두 **서사에 얼마나 나왔나**이며 능력·공헌도·전투 참여 횟수가 아니다.

### 7.2 상황 특화 지표 (키워드 동시 출현)
이름이 들어간 문단(정사는 문장)에 아래 글자 중 하나가 함께 나오면 1로 센다.

| 지표 | 키워드 | 전력 점수에 포함 |
|---|---|---|
| 수전 | 船 · 舟 · 水軍 · 艦 | O (기본 가중치 3) |
| 화공 | 火 · 燒 · 焚 | O (기본 가중치 3) |
| 계책 | 計 · 謀 · 策 | O (기본 가중치 2) |
| 바람 | 風 | X — 사람의 능력이 아닌 환경 조건으로 보고 별도 가정으로 다룸 |

### 7.3 자료 렌즈(같은 지표를 세는 세 가지 범위)

| 렌즈 | 범위 | 단위 |
|---|---|---|
| `yy` 연의 | 43~50회 등장 문단 | 문단 |
| `jb` 정사 본문 | 정사 전기에서 〈 〉 주석을 뺀 부분 | 문장 (`。！？`로 분할) |
| `jn` 배송지 주석 | 〈 〉 안의 텍스트 | 문장 |

연의(문단)와 정사(문장)는 단위와 범위가 달라 **절대값이 아닌 비중(%)으로만 비교**한다.

### 7.4 근거 문단 선정 기준
- 인물·지표마다 키워드가 들어간 연의 문단 중 **한국어 번역이 있는 가장 짧은 문단** 하나를 근거로 보여 준다(최대 210자, 넘으면 말줄임).
- 번역이 없는 문단은 근거로 쓰지 않는다.

## 8. 분석 대상(명단) 선정 기준

| 규칙 | 기본값 | 학습자가 바꿀 수 있는 값 |
|---|---|---|
| 최소 등장 회차 수 | **2회 이상** | 1회 이상 ~ |
| 사망 인물 | **제외** | 제외 / 포함 |
| 진영 | 정사 卷 분류(4.3) | 고정 |

- 사망 인물 목록(적벽대전 208년 기준 이전·당해 사망, 하드코딩): 董卓(192) · 呂布(198) · 袁術(199) · 孫策(200) · 袁紹(202) · 郭嘉(207) · 劉表(208). 이들은 회상·언급으로 등장할 뿐이고, 卷 분류상 상당수가 魏로 잡혀 위 진영 수치를 부풀리므로 기본 제외한다.
- 이 기준은 '전투 참여 확정'이 아니라 '기록 기반 선정 규칙'임을 화면에 명시한다.
- 기본 명단 결과: **42명** (위 15 · 오 20 · 촉 7). 1단계에서 정한 명단은 2~6단계 계산에 그대로 이어진다.

## 9. 분석 방법 기준

### 9.1 진영 비교 (평균의 함정)
- 진영별 **합계 · 1인당 평균 · 중앙값**을 함께 보여 준다. 중앙값은 짝수 개일 때 가운데 두 값의 평균.
- 진영별 최댓값 1명을 뺀 값도 비교해 극단값 영향을 확인한다.
- 비교 묶음: `위·오·촉` 3진영 또는 `위 vs 연합(오+촉)`.
- 기본 명단 결과: 1인당 평균 존재감 촉 22.9 · 오 15.6 · 위 10.2. 촉 문단의 56%가 제갈량 한 명의 값.

### 9.2 전력 점수
```
인물 점수 = 수전 × w수전 + 화공 × w화공 + 계책 × w계책     (기본 w = 3 / 3 / 2)
진영 점수 = 명단 내 해당 진영 인물 점수의 합 (또는 1인당 평균)
```
- 기본 결과(연의): 연합 1,255 vs 위 467.
- 해석 주의: 조조의 화공 18은 불에 '당한' 장면의 동시 출현이다. 키워드 동시 출현은 가해·피해를 구분하지 못한다.

### 9.3 민감도 분석
- 세 가중치를 각각 **0~5 정수**로 바꾼 6³ = 216가지 중 전부 0인 경우를 뺀 **215가지 조합**을 모두 계산한다.
- 조합마다 연합 점수 > 위 점수인지 세고, 결과를 `연합 우세 조합 수 / 215`로 보고한다.
- 조건 축: 자료(연의 / 정사 본문) × 집계(진영 합계 / 1인당 평균) × 현재 명단 규칙.
- 판정 문구: 215/215 = 결론 유지, 과반 = 대부분 연합 점수가 높음, 그 외 = 가정에 따라 뒤집힘.
- 기본 결과: 연의·합계 215/215, 정사 본문·1인당 203/215.

### 9.4 출처 비교 (프록시의 한계)
- 같은 명단·가중치로 연의와 정사의 진영별 점수 **비중(%)** 을 비교한다. 예: 촉 비중 연의 20% → 정사 본문 14%.
- 정사는 진위 판정의 정답지가 아니며, 기록이 없다고 사건이 없었다는 뜻이 아니라는 점을 안내한다.

### 9.5 What-if (인물 이동·제외)
```
연합 우세 지수 = 연합 점수 ÷ (연합 점수 + 위 점수) × 100     (분모 0이면 50)
바람 가정:
  - 환경 조건(기본): 바람 발생 시 연합 +10
  - 제갈량의 능력(연의 관점): 제갈량이 있는 쪽에 ±10, 명단에서 빠지면 보너스 없음
결과는 0~100으로 자르고 반올림
판정: 65 이상 = 연합 점수 우세, 45~64 = 점수 비슷, 45 미만 = 위 점수 우세
```
- 조작: 명단 안의 인물 한 명을 다른 진영으로 옮기거나 명단에서 뺀다. 공동등장 관계는 그대로 둔다.
- 기본 결과: 제갈량 → 위 이동 시 연의 83→72, 정사 81→77, 연의+바람을 제갈량 능력으로 볼 때 52.

## 10. 규칙 기반 전투 시뮬레이션 (PRD F03, `frontend/lib/simulation.ts`)

텍스트 지표와 별개인 **학습용 규칙 모델**이다. 계수는 사료에서 추정한 값이 아니다.

| 입력 | 값 | 기준 |
|---|---|---|
| 황개의 거짓 항복 | 성공 / 발각 | 성공 |
| 동남풍 | 발생 / 미발생 | 발생 |
| 조조군 화공 대비 | 0 / 1 / 2 | 0 |

```
화공       = clamp(35 + 항복30 + 바람25 − 대비×18)
함대 피해   = clamp(화공 − 12 + 항복8)
퇴각 피해   = clamp(20 + round(함대피해 × 0.68))
연합 유지   = clamp(42 + round(화공 × 0.5) − 대비×4)
판정: 화공 ≥78 대승 / ≥55 우세 / ≥38 알 수 없음 / 그 외 조조군 우세
```
기준 출력: 90 / 86 / 78 / 87, 연합군의 대승.

## 12. 알려진 한계 (PRD 리스크 절에 연결)

1. **한 글자 지칭 미집계**: `操`, `亮`처럼 한 글자로만 부른 문단은 빠진다. 등장 수가 실제보다 적을 수 있다.
2. **공동등장은 회차 단위**: 같은 회차에만 있으면 실제로 마주치지 않아도 1회로 센다.
3. **진영은 卷 분류**: 정사가 실은 서(書)를 따르므로 실제 소속과 다를 수 있다(사망자 제외 규칙으로 일부 보정).
4. **키워드 = 함께 나온 글자**: 가해·피해, 긍정·부정을 구분하지 못한다.
5. **단위 불일치**: 연의는 문단, 정사는 문장. 비중으로만 비교한다.
6. **번역 범위**: 근거 문단은 번역이 있는 문단 안에서만 보여 준다. 정사 번역은 seed 기준 4명뿐이다.
7. **사망자 목록 하드코딩**: DB가 아닌 프런트 코드(`40-app.js`의 `DEAD`)에 있다.
8. **지표 이원화**: PRD F02와 API는 '등장 회차 수', 학습 프로토타입은 '등장 문단 수'를 기본 지표로 쓴다. PRD에서 둘을 구분해 표기해야 한다.
