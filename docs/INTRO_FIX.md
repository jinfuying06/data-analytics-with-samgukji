# 오프닝 버튼 수정

## 확인한 문제 구조

오프닝을 본 기록이 있으면 이벤트 연결 전에 초기화가 종료되었다. 오프닝의 숨김 상태는 HTML hidden 속성과 CSS display 규칙에 의존했고, 첫 화면의 Canvas 초기화도 필수 버튼 연결보다 앞서 실행되었다. 기존 테스트는 오프닝을 본 상태를 가정해 본문만 검증했다.

## 변경

- 시작하기·건너뛰기 이벤트를 모든 초기화 경로에서 연결한다.
- 버튼을 누르면 즉시 hidden, display:none, aria-hidden을 함께 적용한다. 애니메이션 타이머를 기다리지 않는다.
- 재방문에서도 오프닝 숨김 상태를 명시적으로 적용한다.
- 오프닝 다시 보기 후 바로 닫거나 다시 열어도 이전 타이머가 남지 않는다.
- 시작하기 버튼은 장면 애니메이션을 기다리지 않고 처음부터 표시한다.
- 배경 Canvas를 사용할 수 없어도 오프닝과 본문은 작동한다. 장식 레이어는 포인터 이벤트를 받지 않는다.
- 닫을 때 본문 제목이나 다시 보기 버튼으로 포커스를 이동한다. Tab·Shift+Tab·Escape를 지원한다.
- 학습 진행 기록과 계산 규칙은 유지한다.

## 검증

`tests/intro-controls.cjs`: 시작·건너뛰기, 첫 방문·재방문, 다시 보기, 즉시 닫기, 포커스·키보드, 동작 감소 설정, Canvas 미지원/오류, 저장소 접근 제한을 포함한 20가지 DOM 시나리오 통과.

`tests/latest-site.cjs`: 기존 여섯 단계, 기준 수치·민감도·시뮬레이션·완료 저장 검증 통과.

실제 브라우저의 클릭·레이아웃 검수는 미리보기 supervisor가 없어 미완료다. DOM 검사를 브라우저 실기 검수로 간주하지 않는다.
