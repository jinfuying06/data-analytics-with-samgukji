- 상태: Draft / 구현 기준 초안

- 저장소: `jinfuying06/data-analytics-with-samgukji`

- 이전 문서: PRD v0.1을 개편. 기존 원문 추적 및 데이터 보존 원칙 계승
- 중요 결정: **MVP 전투 연출은 조조·주유 등 개별 장수 캐릭터를 사용하지 않고, 기존 위·촉·오 세력 깃발만 사용한다.** 캐릭터 시스템은 후속 버전으로 미룬다.

## 1. 제품 정의와 목표

**한 줄 정의:** 삼국지의 사건을 읽고, 실제 텍스트 데이터를 직접 분석하고, 가정을 바꾸어 결과를 비교하는 인터랙티브 데이터 분석 학습 서비스.

핵심 경험: **스토리 이해 → 데이터 분석 → 가설 설정 → What-if 실험 → 결과 비교 → 근거·한계 해석**.

첫 방문자가 약 10~15분 안에 적벽대전의 맥락을 이해하고, 등장 회차 데이터에 직접 필터와 집계를 적용하며, 거짓 항복 조건을 바꿔 모델의 결과를 비교하고 그 차이를 설명하도록 한다. 완성도 높은 역사 전투 예측보다 **데이터 분석의 사고 과정과 실험의 설명 가능성**을 우선한다.

### 대상 사용자
- 1차: 삼국지에 관심이 있으며 SQL·Python·통계에는 익숙하지 않은 데이터 분석 입문자
- 2차: 삼국지의 역사적 가정과 전략 시뮬레이션을 즐기는 사용자
- 비대상: 전문 고증 연구용 시뮬레이터, 역사적 승률 추정 도구

### 제품 원칙
1. **질문 우선:** 차트와 데이터 구조보다 궁금증을 먼저 제시한다.
2. **직접 조작:** 카드 넘기기만으로 학습 완료 처리하지 않는다.
3. **근거 추적:** 원문·가공 데이터·모델 규칙을 역추적할 수 있게 한다.
4. **사실과 가정 분리:** 연의 서사, 정사, 측정값, 사용자의 가정, 모델 출력을 별도로 표시한다.
5. **픽셀은 전투에 집중:** 일반 UI는 정돈된 학습·분석 도구처럼, 전투는 세력 깃발 픽셀 애니메이션으로 표현한다.
6. **기존 자산 재활용:** Next.js, FastAPI, SQLite seed DB, 세력 깃발 에셋을 유지한다.

## 4. F02 — 인터랙티브 분석 퀘스트 (P0)

- ID: `ANALYSIS-001`
- 제목: **적벽대전에서 가장 자주 등장하는 인물은 누구일까?**
- 학습 개념: 분석 질문 구성 → 행/열 및 측정 단위 → 필터링 → 그룹별 집계 → 시각화 → 해석의 한계

### 데이터 정의
- 기존 SQLite `yeonui_mentions`를 사용한다.
- 지표: 선택한 회차 범위에서 인물별 **등장한 서로 다른 회차 수**.
- 계산: `SELECT name, COUNT(DISTINCT chapter) AS chapter_count FROM yeonui_mentions WHERE chapter BETWEEN ? AND ? GROUP BY name ORDER BY chapter_count DESC, name`
- 이 수치는 **서사에 등장한 회차 수**이며 전투 참여 횟수, 능력, 공헌도, 실제 언급 문장 수가 아니다.
- 화면에 표시하는 집계 결과는 실제 DB로 산출하며, 예제 하드코딩 배열을 본 데이터인 것처럼 쓰지 않는다.

### 단계
1. '누구를/어느 범위에서/무엇으로 비교하나?' 질문을 확인한다.
2. 회차·인물·원문 발췌로 이루어진 원자료 표에서 한 행의 의미를 확인한다.
3. 기본 43~50회 필터를 사용자가 직접 변경한다(허용 범위는 seed 데이터 안).
4. '집계'를 직접 실행하고 순위표 및 막대그래프를 확인한다.
5. '등장 빈도가 높으면 더 유능한가?' 해석 선택 후, 데이터로 판단할 수 없는 사항을 설명받는다.
6. 사용한 범위·지표·결과·한계를 포함한 분석 요약을 확인한다.

### 인터랙션
- 회차 시작/종료 선택, 실행, 원자료 표/차트 전환, 해석 응답, 근거 패널 열기, 다시 분석
- 필터 상태가 변경되면 이전 결과를 새 결과인 것처럼 표시하지 않는다.
- 빈 데이터, API 오류, 로딩 상태를 안내한다.
- 선택형 과제에 응답하지 않고 다음만 누르면 완료 처리하지 않는다.

**수용 기준**
- AC-F02-01: 실제 DB의 집계 수치와 UI 수치가 일치한다.
- AC-F02-02: 회차 필터 변경 후 재집계하면 결과가 갱신된다.
- AC-F02-03: 표와 그래프는 동일한 데이터로 렌더링된다.
- AC-F02-04: 지표 정의와 분석 한계에 대한 피드백이 존재한다.
- AC-F02-05: 근거 패널에서 원문·출처·집계 기준을 열 수 있다.
- AC-F02-06: 같은 필터에 대해 같은 결과를 재현할 수 있다.

## 5. F03 — What-if 시뮬레이션 (P0)

- ID: `WHATIF-001`
- 주제: **황개의 거짓 항복이 발각되었다면?**
- 목적: 가설을 정하고, 다른 조건을 고정한 채 변수 하나를 바꿔, 규칙 모델의 결과 차이를 살핀다.
- **역사의 다른 실제 결말을 예측한다고 주장하지 않는다.**

### 입력 변수
| 변수 | 타입 | 기준 설정(모델 기준 시나리오) |
| --- | --- | --- |
| 황개의 거짓 항복 | 성공/발각 | 성공 |
| 동남풍 | 발생/미발생 | 발생 |
| 조조군 화공 대비 | 낮음(0)/보통(1)/높음(2) | 낮음(0) |

기본 상태는 '실제 측정값'이 아닌 현재 프로토타입의 **모델 기준 시나리오**로 표기한다.

### 엔진 규칙 v0.1 (현재 코드 기준)
```ts
const clamp = (v: number) => Math.max(0, Math.min(100, v));
const fire = clamp(35 + (surrender ? 30 : 0) + (wind ? 25 : 0) - defense * 18);
const fleetLoss = clamp(fire - 12 + (surrender ? 8 : 0));
const retreat = clamp(20 + Math.round(fleetLoss * 0.68));
const allied = clamp(42 + Math.round(fire * 0.5) - defense * 4);
const outcome = fire >= 78 ? "연합군의 대승"
  : fire >= 55 ? "연합군의 우세"
  : fire >= 38 ? "승부를 알 수 없음"
  : "조조군의 우세";
```
모든 숫자는 **학습용 지수**(0~100)로서 사료에서 관측한 피해율, 실제 승률이 아니다. 근거 없는 가중치에 '역사 검증' 표현을 사용하지 않는다.

기준 출력: 화공 90 / 함대 피해 지수 86 / 퇴각 피해 지수 78 / 연합 유지 지수 87.

### 진행
1. 실험 질문 및 기준 조건 확인
2. 조건 변경 (처음엔 변수 하나만 변경하도록 권장)
3. '실험 실행' 선택
4. F04 세력 깃발 기반 픽셀 연출
5. 기준 시나리오와 변경 시나리오 지표, 변화량, 판정 비교
6. 가중치·계산 경로 및 가정 확인 (F05)
7. 재실험 또는 기준값 복원

**구현 원칙:** 계산 함수를 UI에서 분리해 순수 함수로 테스트하고 버전을 명시한다. 픽셀 연출은 계산 결과만 받아 사용한다.

**수용 기준**
- AC-F03-01: 세 변수 모두 변경과 초기화가 가능하다.
- AC-F03-02: 입력이 같으면 결과가 같으며 점수는 0~100이다.
- AC-F03-03: 기준/변경 지표와 차이가 동시에 보인다.
- AC-F03-04: 판정이 계산 규칙과 일치한다.
- AC-F03-05: 가중치·모델 버전·가정의 성격을 확인할 수 있다.

## 6. F04 — 픽셀 전투 연출: **위·촉·오 깃발 기반** (P1)

**중요한 MVP 범위 결정:** 아직 장수 캐릭터 구성이 완성되지 않았다. **조조·주유 캐릭터나 그 밖의 개별 장수 스프라이트를 MVP 전투에 사용하지 않는다.** 기존 세력 깃발만 활용하며 장수 중심 전투 제작을 선행 조건으로 두지 않는다.

### 자산
- `frontend/public/sprites/factions/`
- 위(魏)·촉(蜀)·오(吳) 깃발 PNG, GIF 및 스프라이트 시트
- 기존 `manifest.json` 및 파일별 사용 규칙 우선 확인

### 전투 진영
- 위(魏) = 조조군
- 오(吳) + 촉(蜀) = 손권·유비 연합을 표시하는 **UI 진영 표식**
- 주의: 적벽대전 시기의 유비 세력은 아직 후대의 '촉한' 국가가 아니므로, 촉 깃발은 현재 사이트의 세력 분류를 이용한 식별 표시이며 시대 명칭상 편의임을 표기한다.

### 연출
- 위 VS (오+촉) 대치 장면에 기존 깃발 애니메이션 배치
- 결과가 연합군 대승이면 위 진영 후퇴와 화공 효과
- 연합군 우세면 위 진영 일부 후퇴
- 승부 불명이면 양쪽 대치
- 조조군 우세면 위 진영 전진, 연합 진영 후퇴
- 전장 이펙트는 장식적 연출로만 사용한다. 추가 전투 계산/승률 결정은 금지한다.
- 연출 건너뛰기, 다시 보기, 모바일 레이아웃 및 `prefers-reduced-motion` 지원
- 연출 실패 시 정적 결과를 표시한다.
- 향후 장수 캐릭터를 추가해도 기존 엔진·데이터 지표가 영향을 받지 않도록 `simulation result → visual scene` 경계를 분리한다.

**수용 기준**
- AC-F04-01: 위·촉·오 깃발이 실제 에셋으로 표시된다.
- AC-F04-02: 위 대 손권·유비 연합 구도를 이해할 수 있다.
- AC-F04-03: 네 가지 모델 판정에 따라 서로 다른 연출이 실행된다.
- AC-F04-04: 장수 캐릭터가 없어도 완전한 MVP 전투 장면을 이룬다.
- AC-F04-05: 건너뛰기, 다시 보기, 모바일, 움직임 감소 대응.
- AC-F04-06: 깃발/연출은 엔진 계산값을 변경하지 않는다.

## 7. F05 — 근거 확인 패널 (P0)

**목표:** 모든 질문에 대해 '그 숫자와 결론이 어디에서 나왔나?'를 설명할 수 있게 한다.

### 근거 분류
1. **연의/정사 원문:** 출처 URL, 회차/권, 인용 문장 및 번역 유무
2. **가공 데이터:** 추출·인물명 매칭·집계 기준, 불확실성
3. **모델 규칙:** 규칙 버전, 수식과 각 변수의 계수, 결과 지표 정의
4. **사용자 가정:** 어떤 조건을 기준값에서 변경했는지

### 인터페이스
- 데스크톱: 우측 사이드 패널, 모바일: 드로어/시트
- 제목, 출처 유형, 관련 인물·회차, 원문 발췌, 링크, 계산 방법, 주의사항
- 분석 화면: 선택 인물의 회차·기록 및 `COUNT(DISTINCT chapter)` 집계 정의
- 실험 화면: 입력 변수와 모델 가중치 및 기여도, 모델 비실측 고지
- 근거 없음과 검토 필요는 임의 값 대신 명확히 표시
- 패널 닫기 후 기존 필터·실험 입력값 유지; 키보드 및 포커스 관리 지원

**수용 기준**
- AC-F05-01: 학습 및 What-if 양쪽에서 패널을 열 수 있다.
- AC-F05-02: 원문 데이터와 모델 가정이 명확히 다르게 표시된다.
- AC-F05-03: 근거 링크와 계산 규칙을 확인할 수 있다.
- AC-F05-04: 패널을 닫아도 작업 상태가 유지된다.
- AC-F05-05: 모바일 및 키보드 탐색이 가능하다.

## 8. 기술·데이터 요구사항

### 기존 구조 재사용
- Next.js/React/TypeScript: `frontend/`
- FastAPI: `backend/`
- SQLite 공개 seed: `data/seed/red_cliff.db`
- 현재 공개 범위: 제43~50회, 등장 인물 63명, 인물 등장 기록 186건(README 기준)
- 원문 전체 및 로컬 가공 DB는 공개 seed와 범위가 다를 수 있다.

### 기존 API
- `GET /api/storylines/red-cliff`
- `GET /api/persons`
- `GET /api/persons/{name}`
- `GET /api/network`

### 신규/확장 API (설계안)
- `GET /api/analytics/appearances?chapter_start=43&chapter_end=50&limit=12` — 실제 DB 기반 그룹별 distinct 회차 집계. 필터 입력 검증, 빈 결과, 정렬 기준 및 원자료 출처 포함
- 기존 `GET /api/persons/{name}` 연계 또는 `GET /api/evidence/person/{name}` — 해당 인물의 등장 근거/회차/원문 URL 반환
- MVP 시뮬레이션은 프런트엔드 순수 함수로 시작하며 별도 서버 실행 API는 필수 아님.

### 비기능
- 결정론적 시뮬레이션 및 단위 테스트
- 필터·집계 API 테스트: 실제 DB 결과와 비교
- 접근성: 입력 라벨, 키보드, 색 외 텍스트 신호, 차트 대체 표
- 반응형: 데스크톱·태블릿·모바일에서 학습과 실험 수행 가능
- 애니메이션 성능 및 감소 설정
- 출처 링크와 모델 버전 확인

## 9. 디자인·UIUX

**방향: Editorial Data Lab × Pixel Battle.** 일반 화면은 미니멀하고 가독성 높은 현대적인 학습 도구, 전투 장면에는 기존 픽셀 깃발 사용.

- 전투 UI: 깃발과 전장 효과 중심, 픽셀 테두리/게임 폰트를 전체 페이지에 반복하지 않음
- 근거 UI: 출처 구분과 읽기 편한 텍스트 우선

## 10. 성공 기준 (초기 가설)

아래는 실제 측정값이 아닌 첫 사용자 테스트에 사용할 **가설적 목표치**.
- 분석 퀘스트 시작자 중 70%가 완료
- 브리핑 사용자 중 50%가 첫 What-if 실행
- 시뮬레이션 사용자 중 40%가 조건을 변경해 재실험
- 학습 또는 실험 참여자 중 30% 이상이 근거 패널 확인
- 사후 질문에서 70% 이상이 역사적 기록과 학습용 모델 지수를 구별

추가 질적 검증:
- 인물 등장 회차와 실제 기여도를 구분하는가?
- 결과가 바뀐 이유를 하나 이상의 변수로 설명하는가?
- 픽셀 연출이 재미를 주되 반복 실험을 방해하지 않는가?

## 11. 구현 단계와 릴리스 조건

### Phase 0 — 현행 점검
- 현재 프로젝트 실행/빌드 및 SQLite 스키마 확인
- 학습실의 정적 예시와 실 DB 집계 일치 여부 점검
- 모델 기본 출력 회귀 테스트 작성
- 위·촉·오 깃발 manifest/파일 점검
- 기존 문서와 실제 구현 차이 기록

### Phase 1 — 학습 수직 슬라이스
- 분석 API, 필터/집계 UI, 결과 표·그래프, 해석 질문
- 근거 패널의 데이터 조회 파트 구축

### Phase 2 — 시뮬레이션 수직 슬라이스
- 계산 로직 순수 함수화, 기준/변경 결과 비교
- 모델 가정/규칙 근거 패널 연결

### Phase 3 — 깃발 기반 픽셀 전투
- 위·촉·오 깃발 전투 진영 구성
- 네 가지 결과에 따른 애니메이션, 건너뛰기 및 reduced motion
- **개별 장수 캐릭터 구현은 하지 않음**

### Phase 4 — 통합·검증
- 스토리 → 분석 → 실험 → 근거 사용자 여정
- 데스크톱/모바일/접근성·오류 상태 테스트
- 원문과 가정 구분 검수

### 릴리스 체크리스트
- [ ] 기존 스토리 및 인물 API가 정상 동작한다.
- [ ] 43~50회 적벽대전 브리핑을 제공한다.
- [ ] 학습 퀘스트는 실제 DB에서 필터·집계한다.
- [ ] 표/차트 결과가 같은 수치를 사용한다.
- [ ] 분석 해석에 대한 피드백이 있다.
- [ ] What-if 변수 세 가지의 수정, 비교, 복원이 동작한다.
- [ ] 시뮬레이션 모델 지수를 실제 승률/피해율과 구분한다.
- [ ] **조조·주유 등 개별 장수 캐릭터 없이 위·촉·오 깃발만으로 전투 연출을 구현한다.**
- [ ] 네 가지 판정별 연출이 일관되게 나타난다.
- [ ] 애니메이션을 건너뛰거나 줄일 수 있다.
- [ ] 학습과 실험에서 근거 패널을 열 수 있다.
- [ ] 모바일과 키보드에서 핵심 작업이 가능하다.
- [ ] DB 집계와 시뮬레이션 회귀 테스트를 통과한다.

## 12. 리스크와 미결정 사항

1. **연의와 정사 혼용:** MVP 스토리라인이 연의 기반임을 유지하고 정사 근거는 별도 구분한다.
2. **데이터 품질:** 인물 태깅·별칭·누락 검토 상태를 표시한다.
3. **가정의 임의성:** 현재 시뮬레이션 계수는 교육용이며 역사적 인과 추정값이 아니다.
4. **시대 표기:** 유비 세력을 '촉' 깃발로 표기하는 것은 세력 UI 분류의 편의이며 역사적 국가 시점을 뜻하지 않는다.
5. **학습 편의성:** 분석을 직접 실행하되 과도한 입력 작업은 줄인다.
6. **전투 연출 길이:** 자동재생/실행 버튼 및 시간 길이는 사용성 테스트 후 확정한다.
7. **근거 패널 원문/번역:** 병렬 표시 범위와 번역 검수 정책은 추후 결정한다.
8. **피드백 협업:** 사이트를 보면서 주석으로 UIUX를 검토할 방식은 별도 도구 지원 여부 확인 후 결정한다.

## 13. 첫 번째 사용자 검증 시나리오

방문자는 제43~50회 적벽대전의 사건을 읽고, "어떤 인물이 가장 자주 등장하는가?"라는 분석 질문을 받는다. 직접 회차 범위를 선택하고 SQLite 기록을 집계하여 차트로 확인한다. 빈도와 실제 공헌도를 구분하는 피드백을 받은 뒤, "황개의 거짓 항복이 발각되었다면?" 실험을 실행한다. 위 깃발과 오·촉 깃발로 양측이 표현되는 짧은 전투 장면을 보고 모델 기준과 변경 결과를 비교한다. 근거 패널에서 연의 기록, 데이터 집계 방식, 학습용 규칙을 확인하고 다른 조건으로 재실험한다.

> 제품 완료의 기준은 캐릭터 수나 화면 수가 아니라, 사용자가 데이터에서 질문을 풀고 가설의 영향을 설명할 수 있게 되는 것이다.
