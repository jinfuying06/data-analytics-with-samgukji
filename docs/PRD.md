## 1. 제품 정의

**이름:** 계책록 (부제: 삼국지로 배우는 데이터 분석)

**한 줄:** 『삼국지연의』 원문을 직접 세어 만든 숫자로 "만약 ~였다면?"을 따져 보며, 데이터 분석가가 생각하는 순서를 배우는 8비트 학습·시뮬레이션 게임.

**대상:** 데이터 분석을 처음 배우는 성인. 화면 문구와 활동은 중학교 1학년도 이해할 수 있게 쓴다.

**하지 않는 것:** 코딩, SQL, 수식 입력. 역사적 승패 예측. 고증 연구 도구.

## 2. 제품 원칙

1. **노코드.** 모든 분석은 고르기, 끌어 놓기, 누르기로 한다. 키보드로 쓰는 것은 결론 한 문장뿐이다.
2. **질문이 먼저.** 차트보다 "만약 ~였다면?"을 먼저 보여 준다.
3. **짐작은 판정하지 않는다.** 처음 짐작과 계산 결과를 나란히 둘 뿐, 맞고 틀림을 점수로 매기지 않는다.
4. **실제 데이터.** 화면의 숫자는 모두 공개 seed DB(`data/seed/red_cliff.db`)에서 계산한다. 예시용 가짜 숫자를 쓰지 않는다.
5. **사실과 가정을 나눈다.** 연의 기록, 정사 기록, 내가 정한 기준, 계산 결과를 다른 모양으로 표시한다.
6. **재촉하지 않는다.** 시간 제한, 연속 출석, 순위표, 목숨(하트)을 두지 않는다.
7. **픽셀은 세계와 인물에, 선명함은 숫자와 글에.** 본문·표·차트 눈금은 읽기 쉬운 글꼴로 쓴다.

## 3. 구조

| 역할 | 위치 |
|---|---|
| 본 화면 (게임) | `prototype/game-demo/` |
| 계산 규칙과 데이터의 출처 | `prototype/red-cliff-lab/src/30-data.js`, `40-app.js`, `80-simplify.js` |
| 데이터 생성 | `scripts/build_red_cliff_lab_data.py` (seed DB → 데이터) |
| 정적 배포 | GitHub Pages (`.github/workflows/pages.yml`) |

- 계산(명단, 점수, 연합 우세 지수)은 순수 함수 파일 하나로 모아 게임과 테스트가 함께 쓴다. 지금 게임 데모에 복사된 계산은 이 파일로 옮긴다.
- `prototype/red-cliff-lab`의 화면 층(`70`~`98`)은 새 기능을 더하지 않고, 게임 데모가 기능을 넘겨받으면 은퇴한다.
- Next.js(`frontend/`)와 FastAPI(`backend/`)는 당장 걷어내지 않는다. 인물 도감과 관계망을 게임 안으로 옮긴 뒤 남길지 정한다.

## 4. 핵심 흐름

타이틀 → 프롤로그(이야기와 처음 짐작) → 원정 지도 → 퀘스트 6개 → 계책 보고서

### 퀘스트 6개 (미션: 만약 제갈량이 조조의 편이었다면?)

| # | 퀘스트 | 배우는 기술 | 얻는 도구 |
|---|---|---|---|
| 1 | 두 진영의 인물 구성 | 분석 대상과 기준 정하기 | 붓 (세기) |
| 2 | 등장 기록 비교 | 대표값: 평균과 중앙값 | 주판 (집계) |
| 3 | 배·불·계책 점수 | 지표 만들기와 가중치 | 저울 (가중치) |
| 4 | 점수 규칙 215가지 | 민감도 확인 | 체 (걸러 보기) |
| 5 | 원문 확인 | 숫자의 근거 확인 | 돋보기 (원문) |
| 6 | 제갈량 옮기기와 바람 가정 | What-if와 가정 | 부채 (가정) |

각 퀘스트는 **사례 → 행동 한 번 → 결과 → 방금 한 것의 이름 → 확인 문제** 순서로 진행한다. 확인 문제는 활동을 마쳐야 열린다.

### 계책 보고서

학습자가 고른 값으로 채워지는 한 장짜리 분석 보고서. 질문, 자료 범위, 명단 기준, 지표와 가중치, 민감도 결과, 한계, 처음 짐작과 결과, 결론 한 문장. 이미지나 인쇄로 저장할 수 있다.

## 5. 게임 요소

| 요소 | 내용 | 단계 |
|---|---|---|
| 도구 | 퀘스트를 마치면 도구 하나를 얻는다. 얻은 도구는 자유 실험에서 실제 기능으로 쓴다 | P0 |
| 짐작 일지 | 질문마다 처음 짐작과 결과를 기록한다. 하트·EXP를 대신한다 | P0 |
| 의뢰 게시판 | 실험 질문 9개를 인물의 의뢰로 보여 준다. 예: 주유 "내가 병으로 빠졌다면 졌겠소?" | P1 |
| 블록 조립 | 인물 타일과 '세기·더하기·평균 내기' 블록을 끌어 놓아 분석을 쌓는다. 퀘스트 1·2부터 | P1 |
| 정제 퀘스트 | 같은 사람이 두 이름으로 세어진 기록 합치기(華核/華覈, 玄德=유비) | P1 |
| 인물 도감 | 학습자가 계산한 숫자가 카드에 적힌다 | P2 |
| 기록관의 서고 | 메뉴 대신 장소. 진행에 따라 선반이 채워지고 낮에서 밤으로 바뀐다 | P2 |
| 다음 편 | 관도 또는 이릉 | P3 |

**제거:** 하트(남은 기회 3개), EXP(`완료 수 × 120`).

## 6. 그림

- **대화창 초상화를 먼저 만든다.** 인물당 512×512 PNG 1장. 규격은 `prototype/game-demo/assets/PORTRAIT_BRIEF.md`, 기준 이미지는 기록관(`assets/portraits/archivist.png`).
- 순서: 의뢰 게시판에 나오는 인물부터 (제갈량, 조조, 주유, 황개, 방통, 유비, 손권 등).
- 전신 전투 스프라이트(PNG + GIF 5종)는 보류한다. 기존 로스터와 산출물은 지우지 않는다.
- 초상화가 없는 인물은 지금처럼 한자 이름 패와 세력 깃발로 표시한다.
- **연의 120회 전체에서 한 회차에만 나오는 인물은 개별 초상화를 만들지 않는다** (2026-11-26 결정). 세력별 공용 캐릭터 하나(예: 이름 없는 장수)에 그 사람의 한자 이름 패를 붙여 쓴다. 기준은 분석 표 `mentions`의 회차 수: `select name from mentions group by name having count(distinct chapter) = 1` (2026-11-26 기준 609명 중 143명, 적벽 구간에는 1명). 개별 초상화 대상은 나머지 466명이다.

## 7. 문구

- 해요체·하시지요체를 쓰는 기록관의 말투. 전문 용어는 행동을 마친 뒤 이름으로만 붙인다.
- 실무 용어(필터, 집계, 대표값, 민감도 등)는 화면 본문 대신 도구 설명과 보고서에서 보여 준다.
- 문구 기준은 [COPY_STYLE.md](COPY_STYLE.md)를 따른다.

## 8. 수용 기준

- AC-01: 코딩·수식 입력 없이 처음부터 보고서까지 마칠 수 있다.
- AC-02: 화면의 모든 숫자가 seed DB 계산과 같다(테스트로 확인).
- AC-03: 같은 입력이면 같은 결과가 나온다.
- AC-04: 짐작에 점수를 매기거나 기회를 깎는 장치가 없다.
- AC-05: 퀘스트마다 도구를 하나 얻고, 그 도구를 자유 실험에서 쓸 수 있다.
- AC-06: 보고서에 학습자가 고른 기준과 한계가 적힌다.
- AC-07: 키보드만으로, 그리고 390px 모바일에서 모든 흐름을 마칠 수 있다.
- AC-08: 움직임 줄이기 설정에서 애니메이션이 멈춘다.

## 9. 구현 순서

1. 계산 코어를 순수 함수 파일로 추출하고 게임 데모가 그것을 쓰게 한다. 기존 수치 회귀 테스트(83→72, 52 등)를 붙인다.
2. 하트·EXP 제거, 짐작 일지, 도구 6개.
3. 계책 보고서를 4장의 항목으로 확장.
4. 의뢰 게시판(질문 9개).
5. 정제 퀘스트, 블록 조립.
6. 초상화 (1회 1명, 반복 작업).
7. 서고 화면, 인물 도감.
8. 다음 편.
