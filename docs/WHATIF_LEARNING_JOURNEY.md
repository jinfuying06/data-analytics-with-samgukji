# 하나의 What-if 질문으로 연결한 학습 흐름

## 최종 목적

첫 화면에서 『삼국지연의』 속 인물과 사건의 기록을 분석하고 조건을 바꾸어 다른 가능성을 실험하는 활동을 안내한다. 적벽대전의 기록으로 분석 방법을 배우는 목적은 “만약 제갈량이 조조의 편이었다면?”을 자료와 가정으로 따져보기 위해서다.

역사의 다른 결말을 확정하는 것이 아니라, 사용한 자료·비교 기준·가정을 밝히고 그 조건에서 달라지는 계산 결과를 설명하는 것을 목표로 한다.

## 화면 구성 원칙 (2026-10 개편, `80-simplify.js`)

데이터분석을 모르는 사람도(중학교 1학년 수준) 무엇을 해야 하는지 바로 알 수 있게, 모든 단계를 **구체적인 사례 → 한 번의 행동 → 결과 → 방금 한 것의 이름** 순서로 바꿨다. 설명 문단은 접는다. 단계 맨 위 상자에는 '할 일', '왜'(마지막 What-if와 어떻게 이어지는지), '중요한 점'(가져갈 생각 하나)을 한 줄씩 보이게 둔다.

| 단계 | 먼저 하는 행동 | 그다음 붙이는 이름 |
|---|---|---|
| 1 | 조조·허저·하후연·원소를 셀지 뺄지 고르기 | 기준 정하기 (2회 이상, 사망자 제외 → 42명) |
| 2 | 촉 평균 22.9를 보고 제갈량 빼고 다시 계산하기 (→ 11.7) | 평균의 함정, 중앙값 |
| 3 | 주유의 배·불·계책 글자 수를 보고 점수 정하기 | 지표 만들기 |
| 4 | 친구 세 명의 점수 규칙으로 계산, 215가지 전부 계산 | 민감도 확인 |
| 5 | 조조가 불을 잘 다뤘을지 예상 → 원문 읽기 | 근거 확인 |
| 6 | 제갈량을 조조 편으로 옮기기(83→72) → 바람 가정 바꾸기(72 / 52) | What-if와 가정 |

- 홈은 이야기 한 줄, 질문, 예상 고르기만 남기고 배경·방법 설명은 없앴다.
- 기존 명단 규칙·가중치 조절(1단계 rMin/rDead, 6단계 다른 인물 이동)은 '더 해 보기'로 접어 둔다.
- 계산식은 바꾸지 않았다. 표시만 바꾸는 층이라 `40-app.js`·`70-learning-journey.js` 뒤에 붙는다.
- 아래 내용은 개편 전 설계 기록이며, 단계별 화면은 위 표를 기준으로 한다.

## 홈 — 실험 01의 질문으로 시작

- 첫 화면에 ‘적벽대전 데이터 실험 01 / 만약 제갈량이 조조의 편이었다면?’을 배치한다.
- 데스크톱 홈은 사이드바와 학습 기록 패널을 숨겨 질문과 활동에 집중한다. 단계 화면에서는 기존 탐색을 유지한다.
- 기존 위·오·촉 국기 에셋으로 두 진영을 표현한다. 움직임 감소 설정에서는 PNG를 사용한다.
- 첫 행동은 세 가지 예상 중 하나를 고르는 것이다. 정답 판정은 하지 않는다. 예상을 선택하면 시작 버튼이 활성화된다.
- `S.prediction`에 예상을 저장한다. 기존 브라우저 학습 상태와 같은 localStorage를 사용한다.
- 시작 버튼은 첫 미완료 단계로, 모두 완료했으면 마지막 실험으로 연결된다.
- 적벽대전 배경은 질문 아래에서 짧게 제공한다. 여섯 단계 목록은 접힌 ‘전체 학습 과정’으로 제공한다.
- 자동 오프닝을 없애 첫 방문도 질문에서 시작한다. 오프닝은 별도 버튼으로 열 수 있고 기존 시작/건너뛰기·키보드 동작은 유지한다.
- 루트 URL은 항상 홈을 연다. 단계 해시 링크는 그대로 지원한다.

## 단계 연결

1. 인물 구성: 소속을 바꾸기 전, 두 진영에 어떤 인물이 있는지 확인한다. 명단과 포함 기준을 먼저 보고 기록 예시로 이어진다. 같은 명단으로 이후 기록·역할·조건 변경 전후를 비교한다.
2. 등장 기록: 현재 기록의 차이를 확인하고 평균만으로 판단할 때 놓치는 점을 살핀다. 실제 전투력과 구분한다.
3. 지표: 마지막 소속 변경 때 함께 이동할 비교 점수와 가중치를 만든다.
4. 민감도: 선택한 가중치 하나에만 결론이 의존하는지 점검한다.
5. 근거: 연의의 조조 화공 문단을 읽고, 관련 글자 집계가 능력과 같지 않음을 확인한다. 다른 자료로 바꾸는 활동은 기본 학습에 요구하지 않는다.
6. 실험: 앞 단계의 명단·가중치를 유지해 조건을 바꾸고, 자료·조건·결과를 함께 설명한다.

각 단계의 상단에 최종 질문을 작게 표시하고 ‘이번 활동이 필요한 이유’를 보여준다. 단계에서 남길 것은 접어서 제공하며, 반복적인 인물 질문 연출은 제거한다. 제갈량 소속 변경의 기본 질문으로 돌아가는 버튼은 학습자가 선택한 명단과 가중치를 유지한다. 마지막 설명은 기존 계산 결과를 읽어서 구성하며 계산 공식을 새로 만들지 않는다.

## 예상과 결과의 비교

마지막 실험에서 처음 예상을 현재 계산 결과와 나란히 보여준다. 사용자가 해석을 남기면 `S.reflection`에 저장한다. 시나리오 변경 시 결과는 기존 `#r6`에서 갱신하고, 해석 입력란을 교체하거나 입력 중인 내용을 지우지 않는다. 예상이 없는 기존 사용자는 그 사실을 안내한다. 예상의 옳고 그름을 자동 판정하지 않는다. 초기화하면 예상과 해석도 함께 지운다.

## 검증

- `tests/mission-journey.cjs`: 질문 우선 배치·접힌 과정·예상 저장·진행 상태별 시작·해석 보존·기존 국기 경로, 단계별 목적, 최종 설명 갱신, 명단/가중치 유지, 기본 질문 복귀, 조사 처리, observer 정리 검증.
- 같은 시나리오를 반복 기록해도 서로 다른 조건 비교 활동은 완료되지 않는다.
- `tests/latest-site.cjs`: 기존 수치·여섯 단계·민감도·실험·학습 완료 검증 통과.
- `tests/intro-controls.cjs`: 자동 오프닝 없음·선택 재생·시작/건너뛰기·키보드·재방문 등 20개 오프닝 시나리오 통과.
- 생성 데이터가 기준 GitHub의 `30-data.js`와 동일함을 확인했다.
- 관리형 미리보기 supervisor가 없어 실제 브라우저 시각·모바일 실기 검수는 미완료다.

계산·데이터는 유지하며, 화면 구성은 `12-styles-journey.html`, 학습 연결은 `70-learning-journey.js`에서 담당한다.

## 연의·정사의 역할 — 반영된 구성

기본 여섯 단계는 『삼국지연의』 분석 → What-if 실험으로 이어진다. 홈·단계·사이드바에서 기본 자료가 연의라는 사실을 명시한다. 4단계는 연의의 가중치와 집계 방식을 점검하고, 5단계는 연의 원문으로 지표의 의미를 확인한다. 6단계 완료에 다른 자료 선택을 요구하지 않는다.

What-if 결과와 예상 비교 아래에 접힌 확장 활동을 배치한다. 여기에서 정사 본문으로 실험 자료를 바꾸거나 별도의 `#compare` 화면으로 이동할 수 있다. `#compare`는 기본 6단계의 완료 수를 늘리거나 변경하지 않는다. 기존 명단·가중치·`fs` 계산을 그대로 사용해 자료 내 진영별 점수 비중과 인물별 집계 횟수를 제시하며, 정사 본문/주석 범위를 선택할 수 있다.

현재 구현은 키워드 집계와 비중 비교다. 사건별 원문을 맞추어 사실 여부를 판정하는 기능은 구현하지 않았다. 확장 화면은 공통 내용·서술 차이·해당 자료에서 확인되지 않는 내용을 원문으로 구분하는 방법을 설명한다. 정사가 진위 판정의 정답지가 아니라는 점과, 기록 부재가 사건 부재를 뜻하지 않는다는 점을 안내한다. 연의 43–50회와 인물별 정사 열전은 범위가 다르고, 문단/문장이라는 집계 단위도 다르므로 수치만으로 능력·과장·사실 여부를 판단하지 않도록 표시한다.

공개 SQLite와 기존 생성 데이터는 변경하지 않았다. 새 데이터베이스와 실시간 API 연결은 추가하지 않았다.

## 이야기·조건·방법과 명단 선정 안내

홈의 이야기에는 소설의 배경만 남기고, 제갈량의 소속 변경 가정은 별도 ‘바꾸어 볼 조건’ 영역으로 분리했다. ‘확인 방법’은 인물 구성 확인 → 비교 기준 만들기 → 조건 변경 계산이라는 세 가지 행동으로 구분한다. 예상 선택 아래의 정답 관련 안내 문장은 삭제했다.

1단계는 기준을 바꾸기 전 그 의미를 설명하고, 선택 직후 현재/직전 명단의 인원·등장 문단 합계·1인당 평균과 추가/제외된 이름을 보여준다. 첫 화면에서는 전체 63명과 현재 명단을 비교한다. 원래 `roster()`를 그대로 사용하고, 문단 합계는 인물별 횟수의 합계임을 표시한다. 포함 인원이 늘었다고 전투력이 커진 것은 아니며, 등장 기준을 높이면 적게 등장하는 주요 역할 인물도 제외될 수 있음을 안내한다. 다음 단계와 What-if에서 동일 명단을 써야 하는 이유를 연결한다. 별도 DB나 모형은 만들지 않았다.
