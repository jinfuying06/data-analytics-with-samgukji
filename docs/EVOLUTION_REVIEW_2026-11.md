# 계책록 진화 방향 검토 (2026-11-17)

목표: 데이터 분석 학습이라는 정체성을 지키면서 전문성을 높이고, 8비트 감성의 게임 요소를 지루하지 않게 넣는다.
이 문서는 의견이며, 코드와 데이터는 바꾸지 않았다.

## 1. 지금의 정체성

**한 줄:** 『삼국지연의』 원문을 직접 세어 만든 숫자로 "만약 ~였다면?"을 따져 보며, 분석가가 생각하는 순서를 배우는 앱.

다른 학습 앱이 흉내 내기 어려운 강점은 세 가지다.

1. **직접 만든 실제 데이터.** 정사 283명, 연의 120회 2,696문단 번역, 동시 등장 5,830쌍. 예제용 가짜 데이터가 아니다.
2. **숫자를 의심하게 만드는 설계.** 조조의 '불' 점수가 사실은 불에 당한 기록이라는 반전, 화공을 0으로 만들면 연합군 지수가 오히려 오르는 결과. 지표의 한계를 몸으로 겪게 한다.
3. **짐작 → 계산 → 비교 구조.** 맞고 틀림을 판정하지 않고 처음 짐작과 결과를 나란히 둔다.

게임 요소는 이 세 가지를 키우는 쪽으로만 넣는다.

## 3. 전문성: 무엇을 더 가르칠 것인가

지금 6순서는 기준 → 대표값 → 지표 → 민감도 → 근거 → 가정이다. 분석 실무 흐름에서 빠진 부분은 앞쪽(정제)과 뒤쪽(전달)이다.

1. **정제 퀘스트 추가 (가장 추천).** 이 프로젝트가 실제로 겪은 사건이 그대로 교재가 된다.
   - 華核과 華覈가 다른 사람으로 세어져 네 사람의 전기가 뒤섞인 사고
   - 헌제 劉協은 원문에 이름이 한 번도 나오지 않아 0건으로 집계됨
   - 玄德·孟德 같은 자(字)를 본명으로 합치기
   "데이터는 세기 전에 먼저 맞춰야 한다"를 가짜 예제 없이 가르칠 수 있다.
2. **분석 순서를 블록으로 조립하기.** (2026-11-19 수정: SQL 직접 입력 안은 철회. 대상이 코딩을 모르는 사람이다.) 글자 없는 블록을 끌어 놓아 분석을 직접 쌓는다. 예: 인물 타일을 명단 그릇에 넣고 빼기 → '세기'·'더하기'·'평균 내기' 블록을 순서대로 놓기 → 결과 확인. 코드 문법 없이 "분석은 순서가 있는 작업"을 손으로 익힌다. 처음에는 순서 1·2에만 붙여 본다.
3. **계책 보고서를 실제 분석 보고서로.** 질문, 자료 범위, 명단 기준, 지표와 가중치, 민감도 결과, 한계, 결론 한 문장. 학습자가 고른 값으로 채워지고 인쇄·저장할 수 있으면 결과물이 남는다.
4. **역량 지도.** 순서마다 배우는 기술 이름(필터, 집계, 대표값, 지표 설계, 민감도, 타당도)을 실무 용어와 함께 한 장에 모은다. 화면 문구는 쉬운 말을 유지하고, 지도에서만 실무 용어를 보여 준다.
5. **이미 있는 데이터로 넓힐 주제.** 관계망(동시 등장) 분석, 연의와 정사 비교(자료 편향), 상관과 인과. 새로 수집할 필요가 없다.

## 4. 게임: 스타듀밸리에서 가져올 것과 버릴 것

스타듀밸리가 지루하지 않은 까닭은 경험치 막대가 아니다. **내 공간이 자라고, 도구가 늘고, 사람들이 부탁을 하고, 재촉하지 않기** 때문이다.

| 스타듀밸리 | 계책록에서 | 이유 |
|---|---|---|
| 농장 | 기록관의 서고. 퀘스트를 마치면 선반에 죽간이 꽂힌다 | 메뉴 대신 장소. 진행이 눈에 보인다 |
| 도구 강화 | 붓(세기) → 주판(집계) → 저울(가중치) → 체(필터) → 돋보기(원문) → 부채(가정) | **도구 하나가 분석 기술 하나.** 얻은 도구는 자유 실험실에서 실제로 쓴다 |
| 마을 사람의 부탁 | 인물의 의뢰. "주유: 내가 병으로 빠졌다면 졌겠소?" | 질문 9개가 이미 있다. 목록을 의뢰 게시판으로 바꾸기만 하면 된다 |
| 수집 도감 | 인물 도감. 내가 계산한 숫자가 카드에 적힌다 | 데이터 자체가 수집품이다. 63명에서 283명까지 늘릴 수 있다 |
| 계절 | 편. 적벽 다음은 관도, 이릉 | 120회 번역이 끝나 있어 데이터는 준비되어 있다 |

버릴 것:

- **하트(남은 기회 3개).** 틀리면 깎이는 장치는 "짐작의 옳고 그름을 판정하지 않는다"는 원칙과 충돌한다. 대신 **짐작 일지**를 둔다. 빗나간 짐작이 기록으로 쌓이고, 얼마나 빗나갔는지가 다음 짐작의 재료가 된다.
- **장식뿐인 EXP.** 지금은 `완료 수 × 120`이라 진행 막대와 같은 정보다. 도구와 도감으로 대신한다.
- 연속 출석, 순위표, 시간 제한. 분석은 천천히 의심하는 일이다.

## 5. 화면: 8비트를 어디까지 쓸 것인가

- **픽셀은 세계와 인물에, 선명함은 숫자와 글에.** 긴 한글 본문과 표, 차트 눈금은 읽기 쉬운 글꼴로 둔다. 픽셀 글꼴은 제목, 이름표, 버튼에만 쓴다.
- **차트는 블록으로.** 한 칸이 기록 한 줄인 와플·단위 차트는 픽셀 감성과 잘 맞고, "행이 모여 집계가 된다"를 보여 준다. 게임 데모의 와플(215가지)을 다른 순서로 넓힌다.
- **낮에서 밤으로.** 서고는 밝고 따뜻한 낮(종이, 나무, 먹색)으로 시작해 순서가 진행될수록 해가 지고, 마지막 실험에서 지금의 '강 위의 밤과 불길'로 끝난다. 이미 있는 `--heat` 변수를 시간으로 넓히면 된다.
- **그림은 초상화 먼저.** 대화창 초상화는 인물당 PNG 1장이다. 전신 전투 GIF(인물당 6개 파일)는 학습에 주는 효과에 비해 비용이 크므로 뒤로 미룬다. 의뢰 게시판에 필요한 인물은 9명 안팎이다.

## 6. 구조: 게임을 얹기 전에 할 일

1. **계산을 한 곳으로.** 명단, 점수, 연합 우세 지수 계산을 순수 함수 파일 하나로 뽑아 본 화면, 게임 데모, 테스트가 함께 쓴다. 지금은 게임 데모가 "원본과 같은 규칙"을 복사해 둔 상태라 한쪽만 고치면 숫자가 달라진다.
2. **껍데기를 하나로 정한다.** 게임 데모를 본 화면으로 올릴지, 본 화면에 게임 요소를 넣을지 먼저 고른다. 덧칠 층이 쌓인 본 화면보다 598줄짜리 게임 데모를 코어 위에 키우는 편이 가볍다고 본다.
3. **안 쓰는 것을 지운다.** `Lab.tsx`·`LearningJourney.tsx`·`learning.css`와 그 테스트, 루트의 임시 파일(`_query_out.json`, `sunjian_raw.txt`, `scratch_*`, `tmp/`). 삭제는 승인 후에만 한다.
4. **문서를 맞춘다.** PRD를 v0.3으로 고쳐 이름·대상·범위를 실제 제품에 맞추고, README와 AGENTS의 서비스 이름을 통일한다.
5. **Next.js와 FastAPI.** 배포본은 정적 HTML이고 Next.js는 `/person`, `/network`만 직접 그린다. 도감과 관계망을 본 화면 안으로 옮기면 둘 다 없어도 된다. 지금 당장 걷어낼 필요는 없고, 2번을 정한 뒤 판단한다.

## 8. 결정 사항 (2026-11-19)

1. **대상:** 성인 데이터 분석 입문자. 단, 화면 문구와 활동은 중학교 1학년도 이해할 수 있는 수준으로 쓴다. 코딩·SQL·수식 입력은 요구하지 않는다.
2. **껍데기:** `prototype/game-demo`를 본 화면으로 키운다. `prototype/red-cliff-lab`은 계산 규칙과 데이터의 출처로만 쓴다.
3. **그림:** 대화창 초상화(인물당 PNG 1장)를 먼저 만든다. 전신 전투 스프라이트(GIF 5종)는 보류한다.
4. **SQL 모드:** 철회. 3장 2번의 블록 조립으로 대신한다.
